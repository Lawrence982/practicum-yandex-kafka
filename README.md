# Описание проекта
Проект представляет собой Spring Boot приложение, написанное на Java и использующее Maven для автоматизации сборки.

Основное назначение приложения - интеграция с Apache Kafka при помощи одного продьюсера и двух видов консьюмеров с разными стратегиями обработки сообщений.

Для работы с Kafka использовалась библиотека spring-kafka (org.springframework.kafka).

Для создания образа используется Dockerfile, который разворачивается с помощью Docker Compose.

# Классы и структура:

- deployment/compose.yaml - файл конфигурации, описывающий контейнеры, которые будут запущены в Docker.
- Dockerfile - инструкции для создания Docker образа приложения. 
- pom.xml - файл конфигурации Maven, определяет структуру проекта и его зависимости.
- src/main/resources/application.yaml - файл конфигурации spring boot для хранения настроек.
- src/main/java/ru/yandex/practicum/model/Product.java - структура сообщения, отправляемого в Kafka.
- src/main/java/ru/yandex/practicum/config/KafkaTopicConfig.java - конфигурация для автоматического создания топика.
- src/main/java/ru/yandex/practicum/config/KafkaConsumerConfig.java - конфигурация для создания двух видов консьюмеров.
- src/main/java/ru/yandex/practicum/consumer - классы для обработки сообщений из Kafka.
- src/main/java/ru/yandex/practicum/controller/ProductController.java - класс для удобной оправки сообщений через REST запросы.
- src/main/java/ru/yandex/practicum/service - классы для работы продьюсера (отправка сообщений в Kafka).


# Инструкция по запуску
Установить docker и docker compose.

Выполнить команду из корня проекта:
```
docker compose -f ./deployment/compose.yaml up
```
После сборки и запуска убедиться, что все приложения имеют статус UP
```
docker ps -a
```

Что будет поднято: 
- Кластер Kafka на основе Bitnami образов (kafka-0, kafka-1, kafka-2).
- Kafka UI (графический интерфейс).
- Две реплики java приложения, содержащие по 2 копии каждого консьюмера и продьюсера (порт 8081 и 8082).

Для тестирования приложения и отправки сообщений в Kafka можно использовать приложения по типу Postman.
Пример отправки можно найти в файле "Kafka Unit 1.postman_collection.json".

После выполнения запросов можно увидеть оправленные сообщения через Kafka UI, которая доступна на http://localhost:8080.
Полученные консьюмерами сообщения можно увидеть в логах приложения, используя команду

```
docker compose logs app-1
```

# Принцип работы

Работа продьюсера представлена в классе ProductServiceImpl. Он отправляет сообщения в Kafka и выводит лог об этом.
Именно этот класс вызывается из контроллера ProductController.

Работа сингл консьюмера представлена в классе SingleMessageConsumer. Этот консьюмер считает по одному сообщению за раз и
выводит его на консоль. Коммит оффсета происходит автоматически. 

Работа батч консьюмера представлена в классе BatchMessageConsumer. Этот хэндлер получает пачку сообщений, зависящих от
настроек fetch.min.bytes и fetch.max.wait.ms, которые заданы в классе конфигурации KafkaConsumerConfig. Однако эти 
настройки не дают 100% гарантии, что будет получено именно 10 сообщений (так как размер сообщений может быть разный).
Для решения этой проблемы был написан класс RecordBuffer, который накапливает сообщения в памяти. Как только сообщений
накопится не меньше 10, будет произведен ручной коммит оффсетов.

Для сериализации и десериализации класса Product использованы библиотечные классы JsonSerializer и JsonDeserializer.
Чтобы не прерывать работу Kafka Consumer в случае возникновения ошибки десериализации, использован класс ErrorHandlingDeserializer.

Гарантию доставки сообщений (At Least Once) обеспечивают такие настройки как asks: all и min-insync-replicas: 2. 
В случае проблем на стороне сервера брокера сообщения и необходимости повторной отправки использован параметр retries: 3.
